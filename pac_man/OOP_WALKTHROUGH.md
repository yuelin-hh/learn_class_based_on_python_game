# 从吃豆人理解面向对象

## 1. 对象各做一件事

- `PacMan`、`Ghost`、`Bean` 表示游戏中的角色和物品，保存自己的位置与绘制方式。
- `Map` 保存墙体，回答“两个相邻格子能不能通过”。
- `GameManager` 保存一局游戏的整体状态，负责推进回合、吃豆、碰撞和结算。
- `BattleState` 是传给策略的只读快照，避免策略绕开游戏规则直接修改对象。
- `AStarPathfinder`、`AStarGhostBrain`、`AutoPacManBrain` 负责“思考”，不负责绘制。

这就是面向对象中常见的职责分离：对象隐藏内部数据，通过方法提供有限的能力。
例如策略只调用 `state.neighbors(position)`，不需要知道墙体的二维数组怎样存储。

## 2. A* 鬼怎样追击

每个格子是图中的一个节点，相邻且没有墙的格子之间有一条边。A* 为节点 `n`
计算：

```text
f(n) = g(n) + h(n)
```

- `g(n)`：从鬼的当前位置走到 `n` 已经用了多少步。
- `h(n)`：从 `n` 到吃豆人的曼哈顿距离。
- `f(n)`：经过 `n` 的预计总代价。

程序每次从待搜索集合中取出 `f(n)` 最小的节点，直到找到吃豆人。因为曼哈顿距离
永远不小于真实剩余步数，所以这里的 A* 能找到最短路径。

## 3. 自动吃豆人怎样躲避

`AutoPacManBrain.decide` 每回合做四件事：

1. 算出每个鬼按 A* 和移动节奏会走到的下一格。
2. 枚举吃豆人等待或向四个方向移动的动作，排除相撞和交换位置的动作。
3. 向前模拟若干回合，避免为了眼前的豆子钻进两三步后才封死的走廊。
4. 记住当前豆子目标，计算每个安全动作到目标的路径距离。
5. 综合离豆子的距离、离鬼的距离、可用出口数量、逃生步数和“鬼靠近时的
   紧迫程度”打分，选择得分最高的动作。

目标的记忆非常重要。若每回合都重新选择“最近的豆子”，两个等距豆子可能让
吃豆人来回摆动；保留目标直到吃掉它，才能稳定地清空棋盘。

## 4. 类之间怎样协作

```text
GameManager
  ├─ 创建 PacMan、Ghost、Bean
  ├─ 生成只读 BattleState
  ├─ 调用 PacMan 的大脑 decide(state)
  └─ 调用 Ghost 的大脑 decide(state, ghost_index)

AStarGhostBrain ──使用──> AStarPathfinder <──使用── AutoPacManBrain
```

游戏规则和策略通过 `BattleState` 解耦。因此可以替换成键盘控制、随机策略或其他
算法，而不需要改动地图、碰撞和绘制代码。
